# hybrid_rag_review_v10 改进说明

## 一、问题来源

S1302 人工错误注入评测共设置 30 个金标错误。v9 首轮结果暴露出三类主要问题：

1. 合规性错误严格命中 3/12，尤其容易漏掉许可性反向措辞和安全数值阈值；
2. 错别字注入错误实际命中 9/10，但重叠 Chunk 会重复报同一物理位置，且存在格式、扩写、术语存疑等高噪声候选；
3. 8 个精确复制段落全部未被重复智能体正确命中，原因是原逻辑使用整 Chunk 向量相似度，单段重复被长 Chunk 上下文稀释。

评测器还存在跨类型预测抢占问题，例如正确的“通疯→通风”被长 Chunk 的重复告警抢占。

## 二、v10 实现

### 1. 高风险检查并入合规初审

- 保留 v9 初审、数值工具和核验智能体，v10 不再调用前端未消费的法规立场分类智能体；
- 在初审调用前由代码筛出以下高风险片段，并作为“强制逐句核查清单”直接加入初审提示词：
  - “允许、可以、可继续、无需、不必”等许可性措辞与带电、停风、透水等危险动作组合；
  - 瓦斯、甲烷、报警、断电、复电、压力、风量等安全主题中出现具体数值阈值；
- 不再在初审合规后追加独立漏检复核调用，避免与反向数值核验重复执行；
- 初审发现的候选仍经过数值工具和原核验智能体，控制误报；
- 法规最终上下文由 Top-5 扩大到可配置 Top-8，环境变量为 `V10_TOP_K`。

### 2. 批量复核错别字智能体

- 候选先经过确定性代码过滤和 Chunk 内去重，再通过一次批量质量控制调用统一裁决；
- 同一 Chunk 无论产生多少错别字候选，复核阶段最多调用一次大模型；
- 明确过滤单位大小写、编号、公式、排版、简称扩写、语句润色和不确定专业术语；
- 建议必须是唯一、简短、局部可替换的正确字词；
- 每个 Chunk 的完成日志记录“初筛候选数/代码过滤后数量/批量保留数”，并列出最多10个初筛词和保留词，用于定位候选生成或复核阶段的漏检；
- Worker 按“错误原文 + 建议 + Word block定位”线程安全去重，只消除重叠 Chunk 对同一物理位置产生的重复告警，不合并不同位置的真实错误。

### 3. 段落级精确重复智能体

- 不再默认使用整 Chunk 语义相似度作为重复告警主依据；
- 直接读取 Worker 映射的 Word `source_units`，对规范化后的完整段落建立索引；
- 同一 Word block 被相邻 MinerU Chunk 重叠携带时自动排除；
- 每组重复只生成一条问题，同时保留源段落和重复段落的全部 Word block；
- 默认最短检测长度为 30 字，可通过 `V10_EXACT_DUPLICATE_MIN_CHARS` 调整。

### 4. 评测匹配修正

- 评测器先进行同类型一对一匹配，再允许剩余结果跨类型匹配；
- 错别字允许最小 2 字替换片段与完整金标词组匹配，例如“通疯”可以匹配“通疯系统”；
- 避免长重复 Chunk 抢占正确错别字预测。

### 5. 评测性能隔离

- 自动评测启动 Worker 时设置 `V9_DISABLE_ESCALATION_LOOP=1`；
- 只关闭评测进程中的后台主智能体升级队列，正常前端运行不受影响；
- 避免历史升级待办和本轮升级项并发调用大模型，污染主审查链耗时与限流数据。

## 三、运行方式

v9 API 和 SQLite 队列保持兼容，Worker 通过环境变量加载 v10 引擎。建议直接运行：

```powershell
powershell -ExecutionPolicy Bypass -File rag_eval\run_manual_error_injection_eval_v10.ps1
```

报告默认输出到：

```text
rag_eval\reports\s1302_manual_error_eval_v10
```

## 四、已完成验证

- `python -m py_compile`：v10引擎、Worker、评测器和测试文件全部通过；
- `python -m unittest rag_eval.tests.test_hybrid_rag_review_v10 rag_eval.tests.test_manual_error_injection_eval_v1`：21项测试全部通过；
- 真实S1302数据离线回放：174个MinerU Chunk全部成功映射`source_units`；
- 对3102个Word块执行结构化规则离线回放，仅命中9个高风险位置：6个上一轮合规漏检，以及C004、C010、C012三个已命中错误；未额外命中普通正文；
- 段落级精确检测发现37组完全重复，其中人工注入的R001至R008共8组全部命中，即精确重复召回由0/8提升为8/8。

37组中除8组人工注入外，其余包含原始文档已有的完全重复。它们不能直接认定为误报；若只评价人工注入增量，应再运行未注入原文作为对照组，并从注入版结果中扣除两版共有重复。

上一轮批量复核/合并初审优化已完成在线评测，严格P/R/F1为20.18%/76.67%/31.94%，内部总耗时518.54秒。本次新增结构化规则和状态一致性修复尚未重新执行在线评测，预期结果仍需以再次运行v10一键评测后的报告为准。
